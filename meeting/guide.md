# Git 작업 흐름 가이드

## 전체 흐름

1. 작업 목록을 이슈 테이블에서 찾는다
2. 이슈를 작성한다
3. 이슈에 대응하는 브랜치를 깃허브에서 새로 만들고, 로컬에 받아서 체크아웃한다
4. 로컬 브랜치에서 파일을 작성한다
5. 작업을 완료했다면 commit과 push를 깃허브 브랜치에 올린다
6. Pull Request(PR)를 작성한다
7. 구성원이 Merge 처리를 한다

> **예시 상황**
> 이해를 돕기 위해 `feature-1`이라는 기존 브랜치에서 `C3` 이슈 코드인 `seed.ts` 생성 기능을 개발해 합치는 상황을 가정합니다.

---

## 1. 작업 목록 찾기

1. 프로젝트 wiki 페이지 또는 `README.md`의 이슈 목록표 항목에서 링크를 눌러 문서를 확인합니다.
2. 이슈 문서에서 내가 작업하려는 이슈 내용을 찾아 코드를 확인합니다.
3. 코드가 확인되었다면 이슈를 생성합니다.

---

## 2. 이슈 만들기

### 제목 규칙

```
[{합쳐질 브랜치}/{코드}] {이슈 내용}
[{합쳐질 브랜치}-{코드}] {이슈 내용}
```

**예시** — `feature-1` 브랜치에 합칠 `C3` 이슈를 작업하고, C3의 내용이 `seed.ts` 생성이라면:

```
[feature-1-C3] seed.ts 생성
```

### 내용 작성

- 해당 이슈 작업을 설명합니다.
- 없던 이슈를 새로 만드는 경우, 그 작업이 필요한 이유를 설명합니다.

---

## 3. 브랜치 만들기

이슈를 만들었다면 이 이슈에 대응하는 브랜치를 생성해야 합니다. 방법은 두 가지입니다.

### 방법 1 — 이슈 페이지에서 생성

이슈 페이지 우측 `Development` 항목에서 `Create branch`를 눌러 새 브랜치를 만들고 할당합니다.

### 방법 2 — Code 탭에서 생성

1. 리포지토리 첫 페이지인 `Code` 탭으로 이동합니다.
2. `Branches` 버튼을 눌러 생성된 브랜치들을 확인합니다.
3. `New branch`를 눌러 작업할 브랜치를 생성합니다.

### 브랜치 이름 규칙

```
{기존 브랜치}-{이슈 코드}
```

**예시**

- `feature-1-C3`
- `feature-1/C3-create-seed` — 계층 구조를 알 수 있게 만들면 더 좋습니다

기존 브랜치명과 개발 이슈 코드가 확인되도록 만들어 주세요. 이 문서에서는 `feature-1/C3` 브랜치를 생성했다고 가정합니다.

### 주의 — source 브랜치

브랜치 생성 시 source가 되는 브랜치를 **main이 아니라 나중에 합칠 대상 브랜치로 변경**해야 합니다.

`feature-1`에 나중에 합칠 예정이라면, `feature-1`의 원본을 복사해서 기능을 추가로 개발해야 하므로 `feature-1`이 새 브랜치의 source가 됩니다.

브랜치를 만들고 이슈와 연동해 두면 나중에 커밋 기록이 올라갈 때 코멘트로 기록이 자동으로 남습니다.

---

## 4. 로컬에서 작업하기

브랜치를 깃허브에서 만들었다면, 내 컴퓨터에서 작업하기 위해 그 브랜치를 가져와야 합니다.

1. **pull - fetch**로 원격 리포지토리(깃허브)에 생성된 최신 브랜치 정보를 가져옵니다.
   - pull - merge가 아니라 **pull - fetch**로 가져오는 것을 권장합니다.
2. 생성한 브랜치 `feature-1/C3`으로 **checkout**합니다.
   - `feature-1`의 코드를 복사해 왔기 때문에 파일 구조의 변화는 일어나지 않습니다.
   - extension이나 터미널을 확인해서 `feature-1/C3`이 확실히 선택되었는지 확인해 주세요.
3. 확인이 되었다면 작업을 해서 코드를 변경합니다.

---

## 5. commit 후 push

1. 작업을 완료했다면 **staging** 후 **commit**으로 내 로컬 git 리포지토리에 파일을 저장합니다.
2. **push**로 원격 git 리포지토리인 깃허브에 올립니다.
   - `feature-1/C3`에서 작업한 내용을 깃허브의 `feature-1/C3`으로 push합니다.

---

## 6. PR 만들기

깃허브에서 `feature-1/C3`에 변경사항이 반영된 것을 확인했다면, 이 브랜치 내용을 `feature-1` 브랜치에 합쳐야 합니다. 이 과정을 Pull Request로 진행합니다.

1. `Pull requests` 탭으로 이동합니다.
2. 새로운 PR을 만듭니다.
3. **제목** — 자동완성을 그대로 써도 무방합니다.
4. **내용** — 작업한 내용이나 변경사항을 간단히 기록합니다.
   - 예시 작업의 경우: `type.ts 작성`, `seed.ts 생성`

---

## 7. Merge 및 마무리

- 팀원 중 한 명이 PR을 merge 처리합니다.
- 이슈에 브랜치를 연동했다면 **자동으로 이슈가 close**됩니다.
- 연동하지 않았다면 직접 이슈를 닫고, 작업했던 브랜치를 삭제하면 됩니다.

---

## 참고사항

- 요구사항(이슈) 원본은 **아티팩트 분업표**를 참고해 주세요.
- 클로드에게 이슈 질문 시, UI/UX 디자인 프로젝트에서는 아래 양식으로 새 대화를 시작해 주세요.

```text
이슈: [A] 프로필 수정 화면 만들기
브랜치: feat/a-profile-edit
파일: app/(customer)/my/edit/page.tsx
담당: A (손님 앱)

프로젝트 문서에서 구조와 규칙 확인하고, 이 이슈만 처리해 주세요.
이어서 질문 할 내용 입력
```
